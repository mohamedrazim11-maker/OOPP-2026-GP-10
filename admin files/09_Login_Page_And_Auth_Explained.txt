ROLE & PURPOSE:
- Represents the university gateway and authentication entry-point for the Faculty Management System.
- Securely authenticates users (Administrator, Lecturer, Technical Officer, Undergraduate) against
  the database (`users` and `roles` tables).
- Upon successful authentication, polymorphic role dispatching routes the user directly to the appropriate
  dashboard:
  - Role "ADMIN" -> launches `AdminDashboard(user)` (Member 1)
  - Role "LECTURER" -> launches `LecturerDashboard(user)` (Member 2)
  - Role "TECHNICAL_OFFICER" -> launches `TechnicalOfficerDashboard(user)` (Member 3)
  - Role "UNDERGRADUATE" -> launches `UndergraduateDashboard(user)` (Member 4)

5. Login Action Trigger (Lines 680-750)

   - `showErrorMessage(String message)`: Injects error text into `errorLabel` with red highlight and shake animation.
   - `clearForm()`: Clears password and username, resets dropdown to index 0, and clears error labels.

PART 2: LoginController.java
----------------------------------------------------------------------------------------------------
DETAILED LINE-BY-LINE EXPLANATION:

1. Constructor & Dependencies (Lines 20-27)
   - `private final AuthenticationService authService`: Service layer performing password hashing and DB matching.
   - Initialized in constructor `this.authService = new AuthenticationService()`.

2. Login Handler: `handleLogin(...)` (Lines 29-55)
   - Receives `LoginFrame`, `username`, `password`, and `selectedRole`.
   - Step 1: Calls `authService.authenticate(username, password, selectedRole)`. Returns authenticated `User`.
   - Step 2: Calls `redirectToRoleDashboard(user)`.
   - Step 3: Closes login window via `loginFrame.dispose()`.
   - Exception Handling:
     - Catches `ValidationException` (empty username or password) -> displays message on login frame.
     - Catches `AuthenticationException` (invalid credentials or role mismatch) -> displays message.
     - Catches `DatabaseException` (server offline or connection timeout) -> displays alert.

3. Role-Based Dashboard Redirection (Lines 64-95)
   - Extracts `roleName = user.getRole().getRoleName()`.
   - Uses `SwingUtilities.invokeLater(...)` for thread-safe GUI dispatch.
   - Switch Statement (Polymorphism):
     - `case Role.ADMIN`: Instantiates `new AdminDashboard(user).setVisible(true)`.
     - `case Role.LECTURER`: Instantiates `new LecturerDashboard(user).setVisible(true)`.
     - `case Role.TECHNICAL_OFFICER`: Instantiates `new TechnicalOfficerDashboard(user).setVisible(true)`.
     - `case Role.UNDERGRADUATE`: Instantiates `new UndergraduateDashboard(user).setVisible(true)`.

4. Static Entry Point: `showLogin()` (Lines 98-106)
   - Thread-safe launcher method: `SwingUtilities.invokeLater(() -> new LoginFrame(new LoginController()).setVisible(true))`.
   - Called by sign-out buttons across all four dashboards.

PART 3: AuthenticationService.java
----------------------------------------------------------------------------------------------------
DETAILED LINE-BY-LINE EXPLANATION:

1. Credentials Verification & Business Rules
   - Validates that `username` and `password` are non-null and non-empty.
   - Queries `UserDAO.findByUsername(username)`.
   - If user does not exist, throws `AuthenticationException("Invalid username or password.")`.
   - Checks account status: If `status.equalsIgnoreCase("INACTIVE")`, throws `AuthenticationException("This account has been deactivated. Please contact the Administrator.")`.
   - Verifies password match: Compares entered password against stored hash/password.
   - Enforces Role Verification: If user selected a specific role dropdown in the login window, verifies that `user.getRole().getRoleName()` matches the selected role. If not, throws `AuthenticationException("Access denied: User account is not registered under the selected role.")`.

----------------------------------------------------------------------------------------------------
PART 4: AuthenticationException.java
----------------------------------------------------------------------------------------------------
- Custom checked exception extending `Exception`.
- Used to distinguish authentication failures (wrong credentials, deactivated account, role mismatch)
  from database communication errors.
